# Android WorkManager startup crash (#258)

## Before: installed preview APK, API 34 x86_64

Reproduced by launching `com.famy.app/.MainActivity`. The crash occurs in
Android's startup provider, before React Native or the splash screen can run.
All exception causes emitted by logcat for this crash are reproduced below;
logcat did not emit a nested `NoSuchMethodException` or any further cause.

```text
java.lang.RuntimeException: Unable to get provider androidx.startup.InitializationProvider: km: java.lang.RuntimeException: Failed to create an instance of class androidx.work.impl.WorkDatabase.canonicalName
Caused by: km: java.lang.RuntimeException: Failed to create an instance of class androidx.work.impl.WorkDatabase.canonicalName
Caused by: java.lang.RuntimeException: Failed to create an instance of class androidx.work.impl.WorkDatabase.canonicalName
```

`km` is the obfuscated exception class as printed by the installed APK, not an
invented deobfuscation. Sanitized local logcat was saved as `crash.txt` in the
task's temporary evidence folder; the APK and raw device logs are not committed.

## APK inspection

Android SDK `apkanalyzer dex packages --defined-only` and `dex code --class
androidx.work.impl.WorkDatabase_Impl` confirm:

- `androidx.work.impl.WorkDatabase_Impl` exists with its original name.
- It extends `androidx.work.impl.WorkDatabase`.
- It has **no constructor** (`.method ... <init>`) in the installed release DEX.
- The crashing obfuscated `sl5.s` startup path calls `Class.forName(...)` then
  `Class.newInstance()`, as confirmed with `apkanalyzer dex code --class sl5`.
- Release prebuild sets `android.enableMinifyInReleaseBuilds=true` and
  `app/build.gradle` uses that property for `minifyEnabled`.

This identifies a missing reflective instantiation entry point, rather than a
missing entire class. The proposed fix preserves exactly this class and its
public no-argument constructor using the existing `expo-build-properties`
`extraProguardRules` setting. R8, WorkManager startup, react-native-maps and
Google Maps remain enabled. No library versions are changed or forced.

The rule is generated by Expo prebuild; no generated Android files are edited
or committed. Tests exercise the installed Expo rule generator and guard the
specific constructor rule without disabling shrinking globally.
