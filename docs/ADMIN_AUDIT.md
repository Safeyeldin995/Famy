# Admin usability audit — Arabic preview, 2026-10-13

Scope: every `/admin` screen in `src/routes/admin*.tsx`, inspected in the real Edge browser through the synthetic `/preview/admin` routes at **390×844** and **1280×800** with `famio_lang=ar`. The [mobile and desktop captures](admin-audit/screenshots/) are baseline evidence, not Production data or proof of authenticated server behavior. No horizontal document overflow was observed at either width; many controls and labels are nevertheless too small or dense to use comfortably.

Severity: **HIGH** blocks a frequent decision or risks an incorrect action; **MEDIUM** materially slows work; **LOW** is polish.

The `/admin` layout (`admin.tsx`) supplies the shell/navigation for all screens. The preview uses synthetic records and does not prove live permissions, data completeness, or mutation behavior.

## Review-page refinement

The Arabic review page at 390×844 is now **3292px high**, down from the previous 4628px capture (1336px / 28.9% shorter). Each section has one compact checked chip and request-changes action; the page has no reason textareas until a rejection is selected. The global rejection opens a reason sheet, and the approval checklist stays above the primary action.

- [Full review page, 390px](admin-audit/calm-provider-review-390.png)
- [Application rejection sheet, 390px](admin-audit/calm-provider-reject-sheet-390.png)

Local Edge preview checks confirmed no horizontal document overflow, Arabic age labels and working hours, exactly one reason field for the selected teaching group, and disabled confirmation until a reason is entered. These checks used synthetic preview data and made no database writes. The private checked-chip toggle uses the existing guarded section-review RPC; clearing a check does not change application status.

## Prioritized delivery plan

1. **Patch 1 — work queue + one-page provider review (this PR).** Make Home a direct-link queue; put the provider decision in one ordered screen; review teaching as groups; add a transaction-scoped admin-only approve-all wrapper that calls existing checks and rejects self-approval. Keep private documents/references within admin only. Verify exact counts, rollback and mobile sizing locally. The migration is created here but **not applied**.
2. **Patch 2 — operational triage.** Simplify bookings/cases/payments into one clear status, reason and next action per card, with status-specific filters and 44px controls on phones. Translate raw statuses/errors, test 390px Arabic and English, and preserve the existing write paths and audit logs.
3. **Patch 3 — catalog/configuration and audit clarity.** Separate launch-service controls from tutoring taxonomy, zones and payment configuration; provide safe explanations and confirmation around impactful changes. Turn audit/monitoring technical rows into plain-language summaries with expandable details. Avoid exposing IDs or private material outside the admin shell.
