# UX friction audit — October 2026

Issue: [#124](https://github.com/Safeyeldin995/Famy/issues/124). Audited locally on 2026-10-05 from `main` at `4be6519d419b475294ab63fb454db48a3b6c19ba`, including the merged [#123 price picker](https://github.com/Safeyeldin995/Famy/pull/125).

The first priorities are to explain what stops progress, reduce unnecessary form work, and make the next action obvious. Keep server validation, eligibility rules, teaching approval, and financial calculations unchanged. These are proposals for separate, scoped implementation issues; this PR changes documentation only.

## Method and limits of the evidence

- Playwright with `executablePath: '/usr/bin/chromium'`, headless, viewport **390 × 844**. Arabic/RTL first; the same 20 routes then received a quick English/LTR pass.
- Local dev server at `http://127.0.0.1:8094`. Preview enablement was confined to the local server process. Supabase configuration pointed to loopback with a non-secret placeholder; no Production connection, credentials, OTP delivery, payment, or remote mutation was used.
- Each navigation used `page.goto(url, { waitUntil: 'networkidle' })`. The harness selected the locale through the existing `setLanguage` export, then awaited `networkidle` again before recording DOM text, input counts, button dimensions, and screenshots. This deliberately stabilizes language for inspection; it is **not** evidence that SSR language initialization is correct.
- **40/40 page recordings completed**, with Arabic `dir=rtl` and English `dir=ltr`; **0/40 had document scroll width above 390px**. This does not certify every nested panel, form state, keyboard layout, or error state.
- All six provider onboarding steps were traversed using the existing prefilled preview. One price-chip selection was needed to enable the services-step Continue. No final application submission was made. The Admin service creation form was opened but not submitted.
- Requests outside the local server origin were blocked. Map/resource failures under this restriction are environment observations, not evidence of a live outage. Console warnings/errors were retained: 149 resource failures, 37 hydration messages, 280 route code-splitting warnings, two list-key warnings, and one SSR-to-client-rendering message in the 40-route recording. This was an observation run, not an error-free E2E pass.
- The existing preview cannot complete several requested journeys: booking has no selectable published service; search shows a query error; the Admin provider fixture lacks onboarding review data; provider eligibility and tutoring fixtures are incomplete. Family “Add” navigates to `/family-members/new`, outside the preview namespace; further interaction there was not used as evidence. There is no customer booking-detail or family-member form preview route. Those downstream screens were examined in source only. No fabricated fixture or production behavior was added to fill the gaps.
- **B** below means browser-observed; **S** means source-inspected; **C** means supplied by Claude's #125 audit, not independently queried in Production. Field counts exclude typing keystrokes. Tap counts state their start point and exclude scrolling, keyboard input, and OS file/date picker actions. Impact is an estimate of abandonment/error risk, not measured conversion. Effort: S = one contained component/copy change; M = coordinated components and tests; L = policy/schema/workflow work.

Reproduction artifacts were kept outside the checkout in `/tmp/ux124/`: `walk.cjs`, `walk.log`, `screens.json`, `errors.json`, `interact.cjs`, `interactions.json`, and screenshots. Commands: `node /tmp/ux124/walk.cjs` and `node /tmp/ux124/interact.cjs`, both exit 0. The latter captures observations, not a successful end-to-end submission. Temporary artifacts are not required to read this report and may not survive an environment reset.

## Top 10 quick wins — ready for separate implementation issues

Ranked for expected abandonment reduction. Each is frontend-only, S/M effort, and targets a high-impact problem above. Claude and PO should select batches; none is implemented by this audit. Shared copy changes belong in both `src/lib/i18n/locales/ar.ts` and `en.ts`, with no Arabic tashkeel.

### 1. Explain and focus the first incomplete onboarding item — H / M

- **Files:** `src/components/provider/ProviderOnboardingFlow.tsx`, existing onboarding validation/hydration helpers, locales.
- **Change:** show field-specific guidance before submission where existing rules are known; convert completion errors on review into section links. Announce the first failure and focus/scroll to its field. Keep the server authoritative and preserve drafts on failure.
- **Acceptance:** missing reference contact, missing coverage, and missing ID evidence each identify the exact section; one error-link tap opens it without clearing other steps. Arabic/English readers do not get only a generic “complete sections” toast. Valid saved drafts still advance; no new required field is introduced.

### 2. Open documents where the label promises — H / S–M

- **Files:** `src/routes/pro.documents.tsx`, `src/routes/preview.pro.documents.tsx`, `src/components/provider/ProviderOnboardingFlow.tsx`, profile navigation.
- **Change:** use a validated section target to open the existing document/review step directly; display locked-state guidance for approved/non-editable applications.
- **Acceptance:** one tap from “Documents & verification / المستندات والتوثيق” reaches uploads or a clear locked explanation, not step 1. Back and other onboarding entry points retain their defaults. Existing secure upload and edit guards remain unchanged.

### 3. Make optional references visibly optional — H / S

- **Files:** `ProviderOnboardingFlow.tsx`, `src/lib/provider/onboardingReferences.ts` tests, locales.
- **Change:** keep first reference visible; collapse only an entirely empty second reference. Add persistent labels and replace kinship-only Arabic wording. Proposed prompt: “شخص نقدر نسأله عن شغلك / Someone we can ask about your work”. Offer relationship suggestions without rejecting existing free-text values.
- **Acceptance:** first visit displays four reference controls instead of eight; Add another reference expands the second card in one tap. Existing/partially filled second references always remain visible and persist. Missing required first-reference values still block progression with inline hints. No reference requirement is waived.

### 4. Remove no-choice booking stages — H / M

- **Files:** `src/routes/book.$providerId.tsx`, relevant booking step helpers/tests, locales.
- **Change:** skip the requirements stage only after a successful empty result; show optional notes within summary instead of a mandatory stop.
- **Acceptance:** simple no-requirement bookings save two Continue taps (nine stages become seven); bookings with requirements keep their required choices. Query loading/failure never counts as an empty result. Back/Forward preserves date, address, recipient, notes and totals. Tutoring education checks and final confirmation remain intact.

### 5. Give blocked booking screens a next action — H / M

- **Files:** `src/routes/book.$providerId.tsx`, `src/routes/search.tsx`, existing query-error component, locales.
- **Change:** contextual next actions for no eligible services/sessions, no results, unresolved address zone and failed loads. Reuse browse/address paths and preserve filters.
- **Acceptance:** each disabled Continue has an adjacent reason; empty service/session views offer a usable alternative or Back in one tap. Retry retains choices. No button bypasses service approval, zone, or scheduling validation. Verify in complete preview fixtures before claiming runtime coverage.

### 6. Match the payment CTA to the chosen method — H / S–M

- **Files:** `src/routes/book.$providerId.tsx`, `src/components/famio/PaymentBlock.tsx`, payment-copy tests, locales.
- **Change:** replace universal Pay with method-specific action and next-step copy. Proposed cash CTA: “أكد الحجز — الدفع نقدا / Confirm booking — pay cash”. Transfer copy must state that manual review follows receipt submission, consistent with the current flow. Link support in the no-method state.
- **Acceptance:** cash never implies an online charge has happened; transfer never claims automatic confirmation. Existing mutations, amounts, booking transitions, receipt requirements and manual review are unchanged. Load-error and zero-method states remain distinct.

### 7. Make a weekly schedule fast and tappable — H / M

- **Files:** `src/routes/pro.availability.tsx`, existing availability helpers/tests, locales.
- **Change:** enlarge day toggles and introduce “Copy these hours to…” with explicit selected days. Explain rules using examples; collapse advanced rules without changing values.
- **Acceptance:** day/time controls have ≥44px hit areas at 390px RTL/LTR. A user can enter one start/end pair, select five days and apply, then explicitly Save. Copying changes only selected editable days. Existing overlap validation and previously saved schedule remain protected on failed save.

### 8. Show which teaching selection is missing — H / M

- **Files:** `src/components/provider/TeachingCapabilitiesEditor.tsx`, its tests, locales.
- **Change:** persistent labels, dependent-selection guidance, per-query loading/error/empty states and retry; a one-line missing-choice hint beside disabled Save. Replace “approved row” with understandable subject/session wording.
- **Acceptance:** missing subject, curriculum, level or price gives its own next action. A failed taxonomy query never looks like “no subjects”. Save becomes available only for valid choices. Editing approved teaching options still requires Admin reapproval; no approval shortcut or automatic subject creation.

### 9. Reduce customer setup's apparent required work — H / M

- **Files:** `src/routes/setup.tsx`, `src/components/famio/EducationProfileFields.tsx`, setup tests, locales.
- **Change:** group optional school details and address extras behind clearly named expanders; explain the three current required fields. Preserve map/coordinate confirmation and existing values, including autofilled education.
- **Acceptance:** initial view foregrounds name, area and address; optional school/extras are one tap away. Existing populated groups open automatically. Collapsing does not clear or overwrite stored data. Saving the same complete data yields the same payload; no required fields are removed.

### 10. Make missing price limits obvious to Admin — H / S

- **Files:** `src/routes/admin.services.tsx`, focused service warning tests, locales.
- **Change:** add a visible warning for an active service with provider pricing enabled and either minimum or maximum missing; link to the existing edit form. Explain that providers otherwise use a fallback control.
- **Acceptance:** both-null and one-null cases warn; two configured bounds do not. Inactive or Admin-priced services do not receive this warning. One tap opens the right service. No limits are autofilled, no pricing unit inferred, and no service is disabled automatically.
